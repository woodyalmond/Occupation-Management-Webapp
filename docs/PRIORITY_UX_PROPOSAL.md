# Alarmapp 할일 우선순위 UX 제안서

작성일: 2026-04-30

## 결론

`alarmapp`에는 Todoist식 4단계 우선순위나 Eisenhower Matrix(중요/긴급 4분면)를 그대로 넣기보다, 먼저 `오늘 반드시`, `다음에`, `언젠가`의 세 구역을 만드는 것이 가장 적합하다.

이유는 단순하다. 지금 앱의 핵심은 팀 프로젝트 관리가 아니라 개인의 하루 실행과 활동 기록이다. 따라서 사용자가 매번 “중요한가, 긴급한가, 우선순위가 몇 단계인가”를 판단하게 만들면 오히려 피곤해진다. 가장 먼저 필요한 질문은 하나다.

“이 일은 오늘 나를 방해해도 될 만큼 중요한가?”

이 질문에 따라 할일을 세 구역으로 나누면 된다.

- `오늘 반드시`: 오늘 하지 않으면 손해가 생기는 일
- `다음에`: 해야 하지만 오늘 당장 끌어올 필요는 없는 일
- `언젠가`: 아이디어, 후보, 나중에 볼 일

## 외부 조사 요약

Firecrawl로 확인한 기준은 다음과 같다.

- Todoist는 작업이 많아질수록 우선순위가 “무엇을 먼저 할지”를 알려주는 시각 신호가 된다고 설명한다. 또한 Today/Upcoming 화면에서는 높은 우선순위가 위로 올라오고, 필터로 우선순위별 작업을 볼 수 있다. 출처: [Todoist priority](https://www.todoist.com/help/articles/set-a-priority-in-todoist-Wy82Jp)
- Todoist의 Eisenhower Matrix 예시는 `urgent`와 `important` 라벨을 만들고, 네 가지 필터로 나누는 방식이다. 다만 이 방식은 라벨과 필터를 이해해야 하므로 초보 사용자에게는 설정 부담이 있다. 출처: [Todoist Eisenhower Matrix](https://www.todoist.com/help/articles/eisenhower-matrix-with-todoist-kj0Eru)
- Microsoft To Do의 My Day는 오늘 할 일을 매일 다시 고르는 구조다. 오늘 마감인 작업은 자동으로 나타나고, 사용자는 그날의 우선순위를 직접 정한다. My Day는 밤마다 초기화되어 매일 다시 판단하게 만든다. 출처: [Microsoft To Do My Day](https://support.microsoft.com/en-us/office/plan-your-day-with-my-day-4cafa6fe-8891-4ad5-985f-65912146a73e)
- Asana의 Eisenhower Matrix 설명은 일을 `바로 하기`, `일정 잡기`, `위임하기`, `삭제하기`로 나눈다. 핵심은 긴급성과 중요성을 분리해 판단하는 것이다. 출처: [Asana Eisenhower Matrix](https://asana.com/resources/eisenhower-matrix)
- Things는 `Today`, `Upcoming`, `Anytime`, `Someday`를 분리한다. `Today`는 오늘 시작해야 하는 일, `Anytime`은 언제든 할 수 있는 활성 작업, `Someday`는 당장 계획이 없는 일을 보관하는 장소다. 출처: [Things Today, Upcoming, Anytime, Someday](https://culturedcode.com/things/support/articles/4001304/)
- NN/g는 인지 부하(머리가 처리해야 하는 부담)를 줄이려면 불필요한 선택지를 줄이고, 시각적 계층과 점진적 공개(처음부터 다 보여주지 않고 필요한 때 보여주는 방식)를 써야 한다고 설명한다. 출처: [NN/g cognitive load](https://www.nngroup.com/articles/minimize-cognitive-load/)

## 핵심 판단

### 1. “우선순위 숫자”보다 “오늘 끌어올릴지”가 먼저다

우선순위 1, 2, 3, 4는 많은 일을 분류할 때 유용하다. 하지만 개인 앱에서 매번 숫자를 고르게 만들면 입력이 느려진다.

사용자가 할일을 적는 순간에는 대개 생각이 정리되지 않은 상태다. 그때 “P1인가 P2인가?”를 묻기보다 “오늘 할 건가?”만 묻는 편이 낫다.

그래서 1차 구현은 우선순위 숫자보다 `bucket`(담을 칸)을 추천한다.

- `today_must`: 오늘 반드시
- `next`: 다음에
- `someday`: 언젠가

### 2. 마감일은 우선순위가 아니다

마감일이 오늘이라고 해서 항상 중요한 것은 아니다. 반대로 마감일이 없어도 중요한 일이 있다.

따라서 `due_date`(마감일)는 유지하되, `bucket`과 분리해야 한다.

- 마감일: 언제까지 해야 하는가
- bucket: 지금 내 눈앞에 보여야 하는가

이 둘을 섞으면 앱이 “오늘 마감인 사소한 일”을 “오늘 반드시 중요한 일”처럼 보여줄 위험이 있다.

### 3. Someday는 삭제가 아니라 격리다

할일이 30개를 넘으면 문제는 일이 많다는 것 자체가 아니다. 진짜 문제는 “오늘 안 해도 되는 일”이 계속 눈에 보여서 집중을 방해하는 것이다.

`언젠가`는 버리는 곳이 아니다. 머리에서 내려놓고 나중에 다시 볼 수 있게 격리하는 곳이다. Things의 Someday 구조와 GTD(할 일을 신뢰 가능한 외부 시스템에 맡기는 방식)의 Someday/Maybe 사고와 잘 맞는다.

## 추천 UX 구조

### 기록 탭보다 타이머 탭의 할일 영역을 먼저 바꾼다

현재 사용자는 타이머 탭에서 할일을 보고 바로 실행한다. 그래서 우선순위 UX는 기록 탭보다 타이머 탭에 먼저 들어가야 한다.

추천 화면 구조는 다음 순서다.

1. 오늘 반드시
2. 다음에
3. 언젠가

`오늘 반드시`는 항상 펼쳐서 보여준다. `다음에`는 접을 수 있게 하고, `언젠가`는 기본 접힘 상태가 좋다.

이유는 사용자의 눈이 가장 먼저 봐야 하는 것은 “오늘 실행할 것”이지 전체 보관함이 아니기 때문이다.

### 오늘 반드시는 3개 제한을 둔다

UX적으로 가장 중요한 규칙은 `오늘 반드시`를 무한히 허용하지 않는 것이다.

추천 제한은 3개다. 3개를 넘으면 앱이 경고한다.

예시 문구:

`오늘 반드시가 3개를 넘었습니다. 정말 오늘 다 해야 하는 일만 남겨보세요.`

막지는 말고 경고만 한다. 강제로 막으면 사용자가 앱을 우회한다. 하지만 경고는 사용자가 스스로 정리하게 만든다.

### 빠른 입력은 기본값을 `다음에`로 둔다

새 할일을 만들 때 기본값은 `다음에`가 좋다.

이유는 입력 순간의 생각은 대개 “나중에 해야지”에 가깝기 때문이다. 모든 새 할일이 오늘 화면에 들어오면 다시 혼잡해진다.

대신 입력창 옆에 작은 선택지를 둔다.

- 오늘 반드시
- 다음에
- 언젠가

기본 선택은 `다음에`다.

### 오늘 계획 버튼을 둔다

Microsoft To Do의 My Day처럼 하루를 시작할 때 `오늘 계획` 버튼을 두는 것이 좋다.

버튼을 누르면 `다음에` 목록에서 오늘 끌어올릴 후보를 보여준다. 사용자는 1개에서 3개만 `오늘 반드시`로 올린다.

이 흐름이 좋은 이유는 매일 아침 한 번 판단하게 만들기 때문이다. 하루 중간에 계속 우선순위를 재판단하면 피곤해진다.

## 데이터 모델 제안

현재 `tasks`에는 `status`, `due_date`, `created_at`, `updated_at`이 있다. 여기에 다음 필드를 추가하는 것을 추천한다.

```sql
bucket ENUM('today_must', 'next', 'someday') NOT NULL DEFAULT 'next'
```

추가로 정렬을 부드럽게 하려면 다음 필드도 유용하다.

```sql
sort_order INT NOT NULL DEFAULT 0
promoted_at DATETIME NULL
```

각 필드의 의미는 다음과 같다.

- `bucket`: 할일이 어느 구역에 있는지 나타낸다.
- `sort_order`: 같은 구역 안에서 사용자가 직접 정한 순서다.
- `promoted_at`: `오늘 반드시`로 올린 시각이다. 나중에 “오늘 올렸지만 끝내지 못한 일”을 분석할 수 있다.

초기 구현에서는 `bucket`만 넣고 시작해도 된다. 드래그 정렬까지 바로 넣을 게 아니라면 `sort_order`는 2차로 미뤄도 된다.

## API 제안

기존 할일 CRUD(생성, 조회, 수정, 삭제)에 `bucket`을 포함한다.

생성:

```json
{
  "title": "백업 기능 설계",
  "status": "todo",
  "bucket": "next"
}
```

수정:

```json
{
  "bucket": "today_must"
}
```

조회 필터:

```text
GET /api/tasks?bucket=today_must
GET /api/tasks?bucket=next
GET /api/tasks?bucket=someday
```

기록 탭에서는 기존 날짜 필터와 함께 쓸 수 있다.

```text
GET /api/tasks?bucket=today_must&date_from=2026-04-30&date_to=2026-04-30
```

## Flutter UI 제안

### 타이머 탭

타이머 아래 할일 영역을 세 그룹으로 바꾼다.

```text
오늘 반드시
- 백업 설계
- 병원 예약

다음에
- 검색 필터 개선
- README 정리

언젠가
- 모바일 앱 전환 검토
```

각 할일 오른쪽에는 작은 이동 버튼을 둔다.

- `오늘로`: 다음에/언젠가에서 오늘 반드시로 올림
- `다음에`: 오늘 반드시/언젠가에서 다음에로 이동
- `언젠가`: 오늘 필요 없는 일을 숨김

모바일에서는 버튼을 항상 많이 보여주면 복잡해진다. 따라서 할일을 탭하면 하단 액션 시트(아래에서 올라오는 선택 메뉴)로 이동 옵션을 보여주는 편이 좋다.

### 기록 탭

기록 탭에는 검색/필터와 함께 `bucket` 필터를 넣는다.

- 전체
- 오늘 반드시
- 다음에
- 언젠가
- 완료

이렇게 하면 과거에 어떤 일을 “오늘 반드시”로 올렸는지 볼 수 있다.

### Daily Note Markdown

Daily Note에는 할일을 bucket 기준으로 나눠 쓰는 것이 좋다.

```markdown
## Tasks

### Today Must
- [ ] 백업 설계

### Next
- [ ] 검색 필터 개선

### Someday
- [ ] 모바일 앱 전환 검토
```

이 구조는 하루가 끝났을 때 “오늘 반드시로 올린 일을 실제로 끝냈는가”를 보기 좋게 만든다.

## 구현 순서

### 1단계: bucket 필드 추가

DB에 `bucket`을 추가하고 API의 생성/수정/조회에 포함한다.

이 단계의 목표는 UI보다 데이터 구조를 먼저 안정시키는 것이다.

### 2단계: 타이머 탭 할일 3구역 UI

타이머 탭의 할일 목록을 `오늘 반드시`, `다음에`, `언젠가`로 나눈다.

이 단계에서 `오늘 반드시` 3개 초과 경고를 넣는다.

### 3단계: 이동 액션 추가

할일을 다른 bucket으로 옮기는 버튼 또는 액션 시트를 추가한다.

처음에는 드래그 앤 드롭을 넣지 않는 것을 추천한다. 구현 비용이 커지고 모바일에서 테스트할 것이 늘어난다.

### 4단계: 기록 탭 필터와 Daily Note 반영

검색/필터 UI에 bucket 조건을 추가하고, Markdown export도 bucket별로 묶는다.

### 5단계: 오늘 계획 버튼

`오늘 계획` 버튼을 추가해서 `다음에` 목록 중 오늘 끌어올릴 일을 고르게 한다.

이 기능은 가장 멋있지만, 처음부터 넣으면 설계가 커진다. bucket이 안정된 뒤 추가하는 것이 좋다.

## 하지 않는 것을 추천하는 것

### 처음부터 Eisenhower Matrix를 넣지 않는다

중요/긴급 4분면은 이론적으로 좋다. 하지만 현재 앱에서는 너무 무겁다.

사용자는 할일을 만들 때마다 다음을 고민해야 한다.

- 중요한가?
- 긴급한가?
- 위임할 수 있는가?
- 삭제할 일인가?

개인 로컬 앱에서 이 판단은 과하다. 나중에 일이 훨씬 많아지면 `important`, `urgent` 체크박스로 확장하면 된다.

### 우선순위 1, 2, 3, 4를 먼저 넣지 않는다

숫자 우선순위는 정렬에는 좋지만, 사용자가 매번 숫자의 의미를 기억해야 한다.

지금 필요한 것은 숫자가 아니라 시야 정리다. `오늘 반드시`와 `언젠가`가 먼저다.

### 모든 할일을 오늘 화면에 계속 보여주지 않는다

이것이 가장 중요한 UX 원칙이다. 오늘 하지 않을 일은 오늘 화면에서 내려야 한다.

## 최종 추천안

`alarmapp`에는 다음 방식으로 구현하는 것을 추천한다.

1. `tasks.bucket`을 추가한다.
2. 기본값은 `next`로 둔다.
3. 타이머 탭 할일을 `오늘 반드시`, `다음에`, `언젠가` 세 그룹으로 나눈다.
4. `오늘 반드시`는 기본 펼침, `언젠가`는 기본 접힘으로 둔다.
5. `오늘 반드시`가 3개를 넘으면 경고만 띄운다.
6. 기록 탭 검색/필터에 bucket을 추가한다.
7. Daily Note Markdown도 bucket별로 묶는다.

이 방식은 Todoist의 시각적 우선순위, Microsoft To Do의 My Day, Things의 Today/Someday 분리, NN/g의 인지 부하 감소 원칙을 현재 앱 크기에 맞게 줄인 형태다.

가장 중요한 핵심은 이것이다.

사용자에게 “모든 할일”을 보여주지 말고, “오늘 나를 움직일 일”만 먼저 보여준다.
